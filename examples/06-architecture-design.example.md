# 架构设计文档：待办清单（示例）

> 本文件是 `check_architecture.py` 的通过样例，也是一份可直接照改的骨架。
> 场景：单用户待办清单，支持多端访问，后期要加协作与提醒。

## 一、架构总览

一句话：前后端分离的三层单体应用，前端静态托管，后端单体服务按业务域分模块，数据层单库单租户；协作与提醒通过新增模块接入，不改动既有分层。

分层图（文字化）：

```
表现层（浏览器 / 移动端 WebView）
    ↓ HTTP + JSON
接口层（REST 路由、参数校验、鉴权）
    ↓ 调用
业务逻辑层（任务、清单、用户三个域）
    ↓ 调用
数据访问层（仓储接口 + SQL 实现）
    ↓ 读写
基础设施层（数据库、日志、配置、定时器）
```

依赖方向自上而下，**下层不得反向依赖上层**。

## 二、分层架构

| 层 | 职责 | 依赖的下层 | 关键组件 |
|---|---|---|---|
| 表现层 | 渲染界面、发起请求、处理交互态 | 接口层 | 页面组件、状态容器、请求封装 |
| 接口层 | 路由分发、入参校验、身份识别、错误码映射 | 业务逻辑层 | 路由表、中间件、统一响应体 |
| 业务逻辑层 | 领域规则、事务边界、权限判定 | 数据访问层 | 任务服务、清单服务、用户服务 |
| 数据访问层 | 数据读写、查询组装、连接管理 | 基础设施层 | 仓储接口、SQL 实现、迁移脚本 |
| 基础设施层 | 数据库、日志、配置、定时任务 | 无 | 连接池、日志组件、配置加载器 |

## 三、模块划分

| 模块 | 职责 | 对外接口 | 依赖模块 |
|---|---|---|---|
| task | 任务增删改查、状态流转、排序 | TaskService 的五个方法 | user、storage |
| list | 清单创建与归属、任务归组 | ListService | task、user |
| user | 账号、登录态、偏好设置 | UserService、AuthService | storage |
| notify | 到期提醒的触发与投递（二期） | NotifyService | task、user |
| storage | 仓储接口定义与 SQL 实现 | Repository 系列接口 | 无 |

模块之间**只通过接口通信**，禁止跨模块直接读对方的表。

## 四、技术选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| 语言与运行时 | Python 3.11 + 标准库 HTTP 框架 | 依赖少、部署简单，单机能扛住目标量级 |
| 数据存储 | SQLite（单文件） | 单用户场景无需运维；后期换 PostgreSQL 只改数据访问层实现 |
| 前端 | 原生 HTML + 少量 JS | 页面不超过十个，引入框架的收益低于构建成本 |
| 鉴权 | 会话 Cookie + 服务端会话表 | 比 JWT 少一套密钥轮换，登出可立即失效 |
| 部署 | 单进程 + 反向代理 | 与单体架构匹配，避免早早引入容器编排 |

不追求"最流行"，只追求"够用且好扩展"。

## 五、扩展性设计

1. **新增功能挂哪里**：新业务域在业务逻辑层新增模块，在接口层新增路由前缀，在数据访问层新增仓储接口实现；**不修改既有模块的内部实现**。
2. **扩展点定义位置**：任务状态流转做成策略表（状态 → 允许的下一状态 → 触发动作），加新状态只改配置不改判断代码；提醒通道做成接口，加邮件 / 推送只新增实现类。
3. **数据模型演进**：所有表带 `created_at` / `updated_at`；加字段一律可空或带默认值，禁止破坏性改列；结构变更走迁移脚本，脚本按序号命名且可重复执行。
4. **协作场景的预留**：task 表预留 `owner_id`，当前恒为单用户，多人协作时改为按 `owner_id` 过滤即可，不需要改表结构。

## 六、约束与约定

- **目录结构**：`api/`（路由）、`service/`（业务）、`repo/`（数据访问）、`model/`（领域对象）、`migrations/`（迁移脚本），一个文件只属于一层。
- **命名**：接口路径用复数名词 + 动词（`POST /tasks`、`PATCH /tasks/{id}`）；数据库表用单数小写下划线。
- **依赖规则**：跨层调用只允许相邻层；跨模块调用只允许走对方 Service，禁止直接访问仓储。
- **错误处理**：业务错误统一返回 `code` + `message`，不把堆栈暴露给前端。
- **测试**：每个 Service 方法至少一条用例；仓储层用内存实现替换后跑，不依赖真实数据库。
