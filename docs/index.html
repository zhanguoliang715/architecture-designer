architecture-designer

写代码之前先把骨架画对：定分层、定模块边界、定扩展点。产出 06-architecture-design.md，交稿前跑脚本过门禁，缺分层/模块/扩展性直接非 0 退出。

它解决什么问题

架构做错的代价不是"代码丑"，是第二个功能加不进去：分层没定，业务逻辑和 SQL 混在一起，换数据库要改全部代码；模块边界没定，两个模块互读对方的表，改一处崩两处；扩展点没留，加个提醒要动五个文件；选型没写理由，半年后没人敢换。

六节结构

章节写什么
一、架构总览一句话 + 分层图（文字化）
二、分层架构层 / 职责 / 依赖的下层 / 关键组件
三、模块划分模块 / 职责 / 对外接口 / 依赖模块
四、技术选型关注点 / 选型 / 理由
五、扩展性设计新功能怎么加 + 数据模型怎么演进
六、约束与约定目录结构、命名、依赖方向等硬规则

它不是什么

不是通用架构建议。它假定你要交付的是有前后端的中小型 Web 项目；嵌入式、算法库、数据脚本用不上分层与模块这两节。它也不判断选型对错，只要求你写清理由与代价。默认形态是分层单体，不做微服务拆分。
